# 多策略检索系统详解

## 1. 语义检索与 MMR

语义检索是系统的基础检索策略。文档首先通过 Embedding 模型转换为高维向量存入 ChromaDB，查询时同样将用户问题向量化，通过余弦相似度计算与文档向量的距离，返回最相似的 Top-K 个文档块。

### MMR 算法

最大边际相关性（MMR）算法在语义检索基础上增加多样性约束：

- **fetch_k=20**：先从向量库中获取 20 个候选文档
- **lambda_mult=0.7**：相似度和多样性之间的权衡参数，0.7 偏向高相似度
- 算法贪心地选择：既与查询高度相似，又与已选结果不重复的文档

## 2. BM25 关键词检索

BM25 是基于概率检索模型的经典算法，擅长精确关键词匹配。系统使用 rank_bm25 库实现：

- 对所有文档构建 BM25 索引
- 对中文文本使用 jieba 分词
- 与语义检索互补：语义检索擅长同义词和近义表达，BM25 擅长专有名词和精确术语

## 3. HyDE 假设文档嵌入检索

HyDE（Hypothetical Document Embeddings）的工作流程：

1. LLM 根据用户问题生成一篇"理想答案文档"
2. 将该理想文档向量化
3. 用理想文档的向量在 ChromaDB 中检索

**优势**：实际文档和查询可能处于不同的语义空间（用户问的是问题，文档存储的是答案），HyDE 通过生成中间表示来桥接这个语义鸿沟。特别适合问答类场景。

## 4. Multi-Query 多角度检索

LLM 将用户问题从多角度改写为 3-5 个子查询，每个子查询独立检索并合并结果：

- 不同子查询可以覆盖问题的不同侧面
- 如问"如何优化 Python 代码性能"，可能生出子查询：
  - "Python 代码性能优化方法"
  - "Python 多线程和异步编程"
  - "Python 内存管理和垃圾回收"
  - "Python 算法复杂度和数据结构选择"

## 5. 知识图谱检索

知识图谱检索处理结构化知识查询：

1. **实体抽取**：从用户问题中提取关键实体
2. **实体链接**：使用精确匹配、别名匹配和语义相似度匹配在 GraphStore 中定位实体节点
3. **子图提取**：以种子实体为起点，BFS 遍历关联实体（最大跳数 2）
4. **路径推理**：查找连接两个实体之间的多跳路径
5. **上下文生成**：将子图中的实体、属性和关系转换为自然语言描述

## 6. 文档分块策略

系统使用 RecursiveCharacterTextSplitter 进行文档分块：

- **Chunk Size**: 500 字符
- **Chunk Overlap**: 100 字符
- **分隔符优先级**: `\n\n` → `\n` → `。` → `.` → ` ` → ``
- 重叠设计确保跨块的知识不会因切分而断裂

## 7. 检索质量评估

检索结果的最终评估通过两个节点完成：

### 重排序（rerank_documents）

使用 LLM 的 Cross-Encoder 能力对候选文档逐条评分，重新排序：
- 综合考虑文档内容与查询的语义匹配度
- 过滤掉排名靠后的无关文档

### 文档相关性评估（grade_documents）

LLM 二元判断每篇文档是否相关：
- 相关 → 进入生成阶段
- 全部不相关 → 触发降级策略

## 8. 支持的文件格式

系统支持上传和检索以下格式的文档：

| 格式 | 解析方式 | 说明 |
|------|---------|------|
| PDF | PyPDF2 逐页提取 | 保留页面结构 |
| Markdown | markdown → HTML → 纯文本 | 去除格式标记，保留语义 |
| TXT | 按段落分割 | 纯文本，简单高效 |
