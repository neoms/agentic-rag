# 高级 RAG 技术与优化

## 1. 分块策略优化

文档分块是 RAG 系统的基础环节，不同的分块策略对检索质量影响显著：

- **固定大小分块**：最简单的方法，chunk_size=500，overlap=100，对大多数文档适用
- **语义分块**：基于 embedding 检测语义断点，在内容主题切换处分块
- **递归分块**：先按段落分，超长再按句子分，再超长按字符分
- **句子感知分块**：保证每个 chunk 以完整句子开始和结束

当前项目采用递归分块策略，分隔符优先级为：双换行 → 单换行 → 句号 → 空格。

## 2. 检索策略融合

### 2.1 混合检索

混合检索结合了语义检索和关键词检索的优势：

- **语义检索**：捕获语义相似性，同义词自动匹配
- **关键词检索（BM25）**：精确匹配专有名词和领域术语
- **融合方式**：使用 Reciprocal Rank Fusion (RRF) 算法合并两路结果

### 2.2 查询增强

查询增强技术从多个维度改进检索质量：

- **HyDE**：生成假设文档缩小语义鸿沟
- **Multi-Query**：多角度查询覆盖不同侧面
- **Query2Doc**：将查询扩展为伪文档
- **Step-Back Prompting**：先提出更高层次的抽象问题

### 2.3 知识图谱增强

结构化知识能补充纯文本检索的不足：

- 实体关系为答案提供关系性上下文
- 多跳路径推理揭示间接关联
- 子图结构帮助理解实体网络

## 3. 后处理技术

### 3.1 重排序（Re-ranking）

对检索结果进行二次精排，提高最终上下文质量：

- **LLM Cross-Encoder**：逐文档评分，效果最好但耗时
- **BGE Reranker**：专用重排序模型，平衡速度和效果
- **Cohere Rerank**：商业 API，效果好且快速

### 3.2 文档压缩

通过 LongContextReorder 或 LLMLingua 对长文档进行压缩：

- 保留关键信息，去除冗余
- 在 token 窗口内塞入更多有效信息
- 需要小心避免丢失细节

### 3.3 相关性过滤

文档相关性评估确保只有有用的文档参与生成：

- 二元判断（相关/不相关）快速筛选
- 阈值过滤（相似度 > 阈值）
- LLM 逐文档打分

## 4. 自反思与质量保证

### 4.1 幻觉检测

自动检测生成答案是否忠实于源文档：

- **基于提示的方法**：LLM 判断答案中的每个声明是否能在文档中找到支撑
- **基于 NLI 的方法**：用自然语言推理模型判断
- **基于检索的方法**：重新检索判断是否有文档支持

### 4.2 迭代优化

当检测到问题时的修复策略：

- 幻觉 → 重新生成（最多3次）
- 检索不足 → 查询重写后重新检索
- 文档不相关 → 触发联网搜索降级

### 4.3 答案评估

多维度评估生成答案质量：

- 忠实度（Faithfulness）
- 相关性（Answer Relevance）
- 上下文召回率（Context Recall）
- 上下文精确率（Context Precision）

## 5. 内存与对话管理

### 5.1 对话历史管理

使用滑动窗口管理对话历史，保留最近N轮对话：

- 每个 session 独立存储对话历史
- 自动管理消息类型的追加和合并
- LangGraph 的 add_messages reducer 自动处理消息列表

### 5.2 上下文压缩

当对话历史过长时，自动压缩或摘要化：

- 保留最近直接相关的对话
- 早期不相关的对话丢弃或摘要
- 维持有效的 token 预算

## 6. 性能优化

### 6.1 并行执行

LangGraph 的 Send API 支持真正的并行检索：

- 多种检索策略同时执行
- fan-out 分发后各节点独立运行
- fan-in 收敛处自动等待所有节点完成

### 6.2 缓存策略

- Embedding 缓存：同一文本不重复向量化
- 查询缓存：相同问题直接返回缓存结果
- KG 子图缓存：频繁查询的实体关系预热

### 6.3 成本控制

- 轻量模型用于简单任务（实体抽取用 qwen-turbo）
- 重量模型用于复杂任务（答案生成用 qwen-plus）
- 按需调用 LLM，不需要时不调用
