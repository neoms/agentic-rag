# 数据工程核心概念与实践

## 1. 数据管道架构模式

### 1.1 ETL 与 ELT

ETL（Extract-Transform-Load）是传统的数据集成模式：先从源系统提取数据，在中间层清洗转换，最后加载到目标系统。适合数据质量要求严格的场景。

ELT（Extract-Load-Transform）是现代数据栈的主流模式：先加载原始数据到数据湖或数据仓库，再利用强大的计算引擎（如 Spark、BigQuery）进行转换。优势是灵活性高，能保留原始数据用于回溯分析。

### 1.2 Lambda 架构

Lambda 架构将数据处理分为三层：
- **批处理层**：处理全量数据，生成准确的批处理视图（使用 Spark、Flink Batch）
- **速度层**：实时处理增量数据，提供低延迟的最新视图（使用 Kafka Streams、Flink Streaming）
- **服务层**：合并批处理和实时视图，对外提供统一查询接口

适用于同时需要准确性和低延迟的场景。

### 1.3 Kappa 架构

Kappa 架构是 Lambda 架构的简化版本，去除了批处理层，所有处理都在流处理引擎中完成。当需要重新计算时，通过重放消息队列（如 Kafka 的永久存储）来重新处理。Kappa 架构减少了系统复杂性，适合流处理为默认模式的现代系统。

## 2. 数据存储技术

### 2.1 关系型数据库

| 系统 | 类型 | 核心特性 |
|------|------|---------|
| MySQL | OLTP 关系型 | 成熟稳定，InnoDB 引擎，主从复制 |
| PostgreSQL | OLTP 关系型 | 高级SQL特性，JSON支持，强大的扩展性 |
| StarRocks | OLAP MPP | 极速多维分析，向量化引擎，物化视图 |

### 2.2 NoSQL 数据存储

| 系统 | 类型 | 核心特性 |
|------|------|---------|
| MongoDB | 文档数据库 | 灵活 Schema，强大的聚合管道 |
| Redis | 键值缓存 | 极致性能，丰富数据结构，常用于缓存和消息 |
| Cassandra | 宽列存储 | 线性扩展，高可用，适合时序数据 |
| Neo4j | 图数据库 | 高效的图遍历和关系查询，Cypher 查询语言 |

### 2.3 数据湖与湖仓一体

数据湖以 Parquet、Iceberg、Hudi 等开放格式存储海量原始数据，结合 Delta Lake 的 ACID 事务能力，形成湖仓一体（Lakehouse）架构。湖仓一体的代表方案：
- **Databricks Delta Lake**：统一批和流处理，ACID 事务
- **Apache Iceberg**：开放表格式，支持隐藏分区和时间旅行
- **Apache Hudi**：面向增量数据处理的表格式

## 3. 数据治理

### 3.1 元数据管理

元数据是"关于数据的数据"，分为三类：

- **技术元数据**：表结构、字段类型、分区信息、数据量、更新时间
- **业务元数据**：业务定义、数据所有者、数据分类、敏感级别
- **操作元数据**：ETL 运行日志、数据质量检查结果、访问记录

常用的元数据管理工具包括 Amundsen、DataHub 和 Atlas。

### 3.2 数据血缘

数据血缘追踪（Data Lineage）记录数据从源头到消费端的完整流转路径：
- **列级血缘**：追踪字段级别的转换逻辑
- **表级血缘**：追踪表与表之间的依赖关系
- **任务级血缘**：追踪调度任务之间的依赖关系

数据血缘在数据治理、影响分析和合规审计中扮演关键角色。

### 3.3 数据质量

数据质量管理框架通常包含六个维度：
1. **完整性**：数据是否完整无缺失
2. **准确性**：数据是否反映真实情况
3. **一致性**：跨系统的同一数据是否一致
4. **及时性**：数据更新的时效性
5. **唯一性**：数据是否有重复
6. **有效性**：数据是否符合预定义的格式和范围

## 4. 实时数据处理

### 4.1 消息队列

Apache Kafka 是分布式消息系统的行业标准，支持万亿级消息吞吐：
- 发布订阅模式，支持多消费者组
- 持久化存储（可配置保留期）
- 分区机制实现水平扩展
- Exactly-Once 语义支持

Apache Pulsar 是新一代消息系统，在计算与存储分离架构上相比 Kafka 有优势。

### 4.2 流处理引擎

- **Apache Flink**：当前主流的流处理引擎，支持事件时间和精确一次处理语义
- **Spark Streaming**：微批处理模式，适合准实时场景
- **Kafka Streams**：轻量级 Java 库，适合嵌在应用中的流处理
- **RisingWave**：流式数据库，支持用 SQL 表达流计算

## 5. 数据仓库建模

### 5.1 星型模型

以事实表为中心，维度表呈星状分布。事实表存储业务度量值（如销售额、交易次数），维度表存储描述性信息（如时间、商品、门店）。查询效率高，易于理解，但存在数据冗余。

### 5.2 雪花模型

星型模型的规范化扩展，维度表进一步拆分为子维度表。降低数据冗余，但增加查询复杂度。适合对存储成本敏感的场景。

### 5.3 Data Vault 模型

面向数据仓库敏捷建设的方法论，将数据分为三类表：
- **Hub**：核心业务实体（如客户、订单）
- **Link**：实体间的关联关系（如客户下单）
- **Satellite**：实体的描述性属性（如客户姓名、电话变更记录）

Data Vault 模型支持并行开发和增量变更，适合大型数据仓库项目。
